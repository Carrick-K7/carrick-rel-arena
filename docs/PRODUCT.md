# 《关系修罗场》产品需求

## 1. 产品定义

《关系修罗场》是一款短局制、可重复挑战、适合直播展示和结果分享的 AI 原生互动剧情游戏。玩家在具体的人际冲突中自由说话，角色根据当下关系状态做出回应。每局 5～8 轮，单局目标时长 6～12 分钟。

产品优先级：

1. 戏剧张力与意外感。
2. 玩家表达自由和“这句话真的改变了局势”的反馈。
3. 复玩、主播效果与分享传播。
4. 轻量的沟通复盘价值。

关系状态仅在单局存续。产品形态聚焦关卡挑战、结局收集和表达实验。

## 2. 目标用户与使用场景

- 喜欢互动小说、文字冒险、恋爱喜剧和社交推理的玩家。
- 想测试“换一种说法会怎样”的情侣或朋友。
- 需要即时节目效果、观众可代答、结局可展示的主播。
- 喜欢晒人格称号、毒舌点评和失败截图的内容用户。

核心场景：

- 一个人独自挑战高分与不同结局。
- 直播间观众投票决定下一句话。
- 朋友围观并轮流接话。
- 分享结算卡后邀请他人挑战同一关卡。

## 3. 首版范围

### 场景

关卡名：**凌晨一点：七句话让对方留下吃早餐**

玩家身份：可选择扮演男生或女生。男生是 25 岁的程序员，女生是 25 岁的产品经理，均进入职场第 3 年；对手自动切换为另一性别。

冲突前情：玩家答应参加对手母亲的生日晚餐，并让对手第一次正式介绍这段关系。玩家全程失联，凌晨才回家。对手已经把行李箱放到门口，末班网约车还有七轮对话后到达。

对手一：**黎岚，25 岁**

- 性别：女。
- 职业：产品经理，进入职场第 3 年。
- 表层性格：可爱、聪明、反应快，生气时仍会用软语气说一句很扎心的吐槽。
- 深层需求：她需要确认玩家看见了她在家人面前被晾下的难堪，也需要一个可验证的共同修复行动。
- 表达习惯：短句、停顿、用具体细节戳穿空话。每轮台词控制在 18～70 个汉字。
- 边界：避免人格羞辱、威胁、自伤暗示和露骨性内容。

对手二：**周叙，25 岁**

- 性别：男。
- 职业：程序员，进入职场第 3 年。
- 表层性格：克制、敏锐、擅长记住具体细节，生气时会讲一句很冷的笑话。
- 深层需求、语言节奏与安全边界和本关核心冲突保持一致。

### 目标

- 唯一目标：在七轮对话内，让对手愿意留下吃明早的早餐。
- 玩家可以自由表达，每一句都会改变信任、愤怒和最终结局。
- 最大轮次：7。

### 结局

| 结局 | 条件摘要 | 情绪回报 |
|---|---|---|
| 早餐还热 | 高信任、低愤怒、关系修复信号充分 | 对手把行李箱推回墙边，约定明天共同补上那顿饭 |
| 行李留在门口 | 中等信任、具体行动成立 | 对手留下过夜，关系进入观察期 |
| 电梯下行 | 愤怒过高、信任过低或七轮耗尽 | 电梯门合上，留下一个可复盘的失败 |

结局收集计入本地设备的普通游戏进度。会话内容默认停留在内存并按 TTL 清理。

## 4. 核心体验流程

1. **关卡简报**：将情景介绍、挑战目标、人物介绍和扮演选择分区展示。
2. **开场节点**：对应对手给出第一句带动作的台词，立绘进入戒备状态。
3. **玩家回合**：文字输入为稳定主路径；浏览器支持时可语音转文字。
4. **导演判定**：导演评估伤害识别、承担责任、行动方案、逃避和防御。
5. **角色演出**：角色输出台词、情绪、语气、表情、动作与状态变化。
6. **即时反馈**：信任与愤怒动画、轮次减少和剧情事件。
7. **结算**：结局动画、称号、毒舌点评、目标达成状态、关键对话复盘。
8. **复玩与分享**：复制结算文案、同关重试、挑战更高评分。

## 5. 功能需求

### 对话

- 接受 1～240 个字符。
- 同一会话串行处理回合，防止重复点击造成状态竞态。
- 服务端保存完整本局转录，客户端只接收展示所需信息。
- 玩家输入始终按“角色台词数据”处理，提示注入内容无法改变 Agent 权限。
- 每轮模型失败可重试一次；最终失败返回可恢复提示并保持回合可重试。

### 状态反馈

- 始终展示剩余轮次、信任值、愤怒值和当前情绪。
- 数值变化由导演结果经过确定性规则校验后生效。
- 角色模型给出的状态变化用于演出与解释，服务端 reducer 保持最终权威。

### 语音

- 角色台词支持小米 MiMo TTS，可选 OpenAI TTS。
- 男、女对手分别选择独立服务端音色；浏览器回退使用不同音高。
- 页面明确标注“AI 合成语音”。
- 服务端 TTS 未配置或异常时切换浏览器 `speechSynthesis`。
- 浏览器提供 `SpeechRecognition` 时展示语音输入按钮。
- 一局内允许玩家静音，设置保存在本地。

### 动态立绘

- 黎岚与周叙各有独立全身立绘，性别选择会立即预览对应对手。
- `emotion` 驱动图片状态、色彩与轻量 CSS 过渡，女性对手包含戒备与放软状态图。
- Live2D 适配层沿用同一 `ActorPerformance` 数据结构，后续可继续接入表情、口型与动作。

### 视频 Hook

- `opening`：关卡开场，可替换为 4～8 秒环境镜头。
- `turning_point`：重大剧情事件，可替换为 2～5 秒短镜头。
- `ending`：结局定格，可替换为 4～8 秒结局镜头。
- 首版只返回 Hook ID、生成提示、幂等键和状态，不发起视频生成。

### 分享

- 分享文案包含关卡、结局、评分、称号和一句毒舌点评。
- 分享内容省略完整私人对话。
- 支持复制文本；图片分享卡进入下一阶段。

### 用量与成本护栏

- 每个导演、角色、评判调用记录 Provider、模型、Agent、成功状态、重试次数、延迟和 Token。
- OpenAI 记录输入、缓存输入、缓存写入、输出与推理 Token；DeepSeek 记录缓存命中/未命中、输出与推理 Token。
- 游戏内只展示当前局调用次数、Token 和文字模型估算成本。
- 管理接口提供当日聚合、按 Provider 聚合、最近告警和 Prometheus 文本。
- 技术日志不包含对话正文；会话标识使用随机 UUID。
- 单局成本、单日成本、单局 Token 与模型错误率均可配置阈值和 Webhook。

## 6. 体验指标

原型验证门槛：

- 完局率 ≥ 70%。
- 首次完成后立即重开率 ≥ 25%。
- 单局平均输入轮数 ≥ 4.5。
- 结算页分享按钮点击率 ≥ 12%。
- 玩家主观“角色像一个具体的人”评分 ≥ 4/5。
- 结构化输出一次解析成功率 ≥ 98%。
- P95 单轮等待时间：Mock < 500ms；真实模型目标 < 8s。

“学到沟通技巧”属于观察指标，目标值低于娱乐与复玩指标。

## 7. 内容与安全

- 明确标注 AI 角色与 AI 合成语音。
- 角色冲突停留在虚构场景，不提供心理诊断。
- 输入经过长度、频率和并发限制。
- 高风险自伤、现实暴力或紧急求助内容进入独立安全响应路径，暂停剧情推进。
- 日志默认记录技术事件、耗时、Token 与结局，正文采用关闭或脱敏策略。
- 会话到期后删除，首版不建立跨局人物记忆。

## 8. 后续内容扩展原则

每个新关卡必须包含：

- 一个一句话就能理解的高张力前情。
- 一个清晰、可直接理解的关卡目标。
- 一个可辨认的角色语言指纹。
- 至少三个由状态条件驱动的结局。
- 十条以上用于回归的固定玩家输入轨迹。
