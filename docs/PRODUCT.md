# 《关系修炼》产品需求

## 1. 产品定义

《关系修炼》是一款短局制、可重复挑战、适合直播展示和结果分享的 AI 原生互动剧情游戏。玩家在具体的人际场景中自由说话，角色根据当前关卡与单局状态回应。每局 5～7 轮，目标时长 6～10 分钟。

产品优先级：

1. 戏剧张力与意外感。
2. 玩家表达自由和“这句话真的改变了局势”的反馈。
3. 复玩、结局收藏、主播效果与分享传播。
4. 轻量的沟通复盘价值。

每局会话、对话、情绪和关系状态完全独立。产品不建立跨局 AI 情感记忆。

## 2. 角色与八关目录

玩家每关均可选择扮演 25 岁、职场第 3 年的程序员男生徐坤，或产品经理女生秋雾；互动伴侣自动切换为另一角色。两位角色贯穿固定的轻连续主线，但前一关台词和数值不会带入下一关。

|---|---|---|---:|---|---|

## 3. 核心体验流程

1. **关卡选择**：八张关卡卡片按类型与完成进度筛选。
2. **关卡简报**：展示情景、唯一目标、人物、难度、轮次与身份选择。
3. **开场节点**：互动角色给出第一句带动作台词，立绘进入戒备状态。
4. **玩家回合**：玩家可随时键入或使用语音转写；语音先转为可编辑文字，无需预先切换输入方式。
5. **导演判定**：导演评估理解需要、具体行动、尊重选择和真诚在意。
6. **角色演出**：角色输出台词、情绪、语气、表情、动作与状态变化。
7. **即时反馈**：关系温度、对话压力、剩余轮次和剧情事件。
8. **结算**：确定性结局、称号、点评、目标判定、关键对话复盘。
9. **复玩与收藏**：同关重试、返回目录、分身份最佳成绩与结局收藏。

## 4. 状态与结局

权威状态统一为：

- `warmth`：关系温度，前端可见。
- `pressure`：对话压力，前端可见。
- `openness`：开放程度，仅供导演与结算使用。

内部评价信号统一为：

- 理解需要。
- 提出具体行动。
- 尊重选择。
- 表达真诚在意。

四类信号只用于评估台词质量，不形成隐藏任务或额外公开目标。每关只有一个公开目标。

每关配置独立初始数值、S/A 成功轮次和门槛。服务端按权威状态锁定 S、A 或 C 结局；导演只能建议结束，角色只负责演出，评判只负责解释和包装。

## 5. 功能需求

### 对话

- 接受 1～240 个字符。
- 同一会话串行处理回合，防止重复点击造成状态竞态。
- 玩家输入始终按“角色台词数据”处理，提示注入无法改变 Agent 权限。
- 每轮模型失败可重试一次；最终失败返回可恢复提示并保持回合可重试。
- 服务端会话默认 120 分钟过期，不建立跨关记忆。

### 关卡选择与进度

- 类型筛选：全部、邀约、安慰、磨合、修复。
- 进度筛选：全部、未完成、已完成。
- 卡片显示编号、标题、简述、轮次、难度、完成状态和男女身份最佳评级。
- 使用 `relationship-training:progress:v1` 保存本机进度。
- 每个身份记录游玩次数、最高分、最佳评级、已见结局和最近游玩时间。
- 最佳评级按 `S > A > C` 合并，结局集合去重。
- 损坏或旧版本数据回退为空进度。
- 清除进度需要二次确认。
- 对话、会话 ID、角色数值和玩家输入不得写入浏览器缓存。

### 模态与演出

- 文字输入与语音转写同时可用，不设置互斥的输入模式。
- 文字输出固定保留；语音、图像和视频可多选并同时启用，媒体生成失败不阻塞对话。
- 角色台词支持小米 MiMo TTS，可选 OpenAI TTS。
- 男女角色使用独立服务端音色；服务端不可用时回退浏览器语音。
- 浏览器提供 `SpeechRecognition` 时展示语音输入。
- 秋雾使用戒备与放软两张仓库内 WebP；徐坤保持单张立绘与 CSS 状态变化。
- 图像输出在开场及每轮回复后实时生成；视频输出也逐轮生成图片，并在结算后一次性生成整局回忆短片。
- 每张图片固定参考秋雾、徐坤原型和可用的上一帧，只做细微情绪变化。对话正文作为临时剧情上下文发送给媒体模型，但模型被要求不渲染文字；准确汉字由页面叠加。
- 固定人物原型由服务端以内联 Base64 发送给 Seedream，避免供应商回源下载超时；生成任务有明确超时、失败与人工重试状态。
- 对话页保留本局全部成功剧情图，玩家可按开场和回合切换查看，不只展示最新一张。
- 图像与视频选项要求服务端配置火山方舟，并由玩家输入产品访问密钥后解锁。
- 媒体访问密钥只保留在当前页面内存；输出组合偏好可保存在本机。
- Seedream 生成 4:5 剧情图像；Seedance 默认生成 480p、16:9、15 秒无声回忆短片。

### 分享与用量

- 分享文案包含关卡、结局、评分和称号，不包含完整私人对话。
- 每次导演、角色、评判调用记录 Provider、模型、Agent、成功状态、延迟和 Token。
- 技术用量日志不记录 Prompt、玩家台词或完整转录。
- 管理接口提供当日聚合、告警和 Prometheus 文本。

## 6. 内容与安全

- 对媒体能力不堆叠技术状态文案；设置页清楚说明语音和实时生成能力。
- 角色冲突停留在虚构场景，不提供心理诊断。
- 避免人格羞辱、威胁、自伤暗示和露骨内容。
- 输入经过长度、频率和并发限制。
- Provider 密钥只保存在服务端；公开页面只接收独立的产品访问密钥。
- 一局结束后，本地只留下普通游戏进度；关系状态到此为止。

## 7. 新关卡原则

每个新关卡必须包含：

- 一个一句话可理解的前情和唯一公开目标。
- 5～7 轮上限。
- 独立初始状态、角色关注点、开场、转折与结局阈值。
- S、A、C 三个确定性结局及完整文案。
- Mock 场景化台词与固定玩家输入回归轨迹。
