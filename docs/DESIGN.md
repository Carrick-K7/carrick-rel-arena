# 《关系修炼》设计系统

本文是前端视觉和交互的单一事实来源。品牌、字体、布局、动效或组件模式改变时，须同步更新本文和 `src/client/styles.css`。

## 1. 设计原则

1. **真实关系，不做数值面板**：界面围绕目标、前情、对话和对方形象组织。服务端可以保留多项内部指标，玩家只看到一条“关系进展”。
2. **初音色但不游戏化堆叠**：`#39c5bb` 是唯一品牌主色，用于选中、进度和关键操作。大面积使用纸白、浅薄荷和青灰。
3. **字体承担叙事层级**：展示字体负责记忆点，黑体负责操作，宋体负责故事。不同字体不混用职责。
4. **内容优先**：桌面端用三栏建立稳定位置；手机按故事、形象、对话顺序线性阅读，不横向滚动。
5. **隐私和技术实现退到幕后**：页面不展示供应商、Token、成本或“AI 实时生成”等技术状态。媒体失败直接回退立绘。

## 2. 品牌

### 2.1 Logo

- 品牌资产为 `public/brand/relationship-training-logo.svg`。
- 标志由两枚相扣的对话气泡组成“关系结”，使用初音青和深青。字标已转为 SVG 路径，不依赖浏览器字体。
- favicon 使用同一枚关系结，位于 `public/favicon.svg`。
- 页面使用 `BrandLogo` 组件；完整宽度约 178px，紧凑版约 138px。不得恢复圆圈“修”字或英文副标。
- 可访问名称统一为“关系修炼”或具体动作，例如“返回关系修炼关卡”。

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f4fbfa` | 页面底色 |
| `--surface` | `#ffffff` | 卡片、聊天和浮层 |
| `--ink` | `#263433` | 主文字 |
| `--muted` | `#607370` | 次要文字 |

关卡类型仅在小标签中使用辅助色：邀约为 teal，安慰为蓝紫，磨合为琥珀，修复为玫红。大面积背景不得跟随类型变色。

## 3. 三层字体体系

字体均为自托管 WOFF2 子集，使用 SIL OFL 1.1。授权文件随静态资源一同发布。

| CSS family / token | 来源 | 使用范围 |
|---|---|---|
| `Relationship Display` / `--font-display` | 得意黑 | Hero 标题、首页章节标题、关卡大编号和少量展示数字 |
| `Relationship Sans` / `--font-sans` | 思源黑体 SC | 导航、正文、筛选、目标、玩家消息、输入框和所有控件 |
| `Relationship Serif` / `--font-serif` | 思源宋体 SC | 场景名、角色消息、开场白、剧情变化和结算叙事 |

约束：

- 得意黑不能进入按钮、正文、聊天和长段阅读区域。
- 角色台词用宋体左对齐；玩家消息用黑体右对齐。
- 生僻字允许回退至 `PingFang SC`、`Microsoft YaHei`、`Songti SC` 等系统中文字体。
- 全部字体使用 `font-display: swap`。首页预加载得意黑和思源黑体 Regular；宋体按 CSS 使用加载。
- 字体资源和授权文件均放在 `public/fonts/`，不使用字体 CDN。

## 4. 首页

### 4.1 信息结构

- 顶栏只显示 Logo 和圆形设置按钮。
- Hero 只有主标题、句子“在一次次真实对话里，练习理解、表达与修复。”和四个优势。
- 场景浏览器桌面端为三栏：筛选、紧凑目录、当前场景详情。
- 卡片点击只改变选中场景；“查看场景”才进入身份简报。

### 4.2 筛选

- 完成状态为单选：全部、未完成、已完成。
- 类型和难度为多选；组内 OR、组间 AND。
- 显示结果数和清除入口。筛选隐藏当前项后选择第一项可见结果。
- `<=1180px` 时筛选变为折叠工具栏；`<=900px` 改为单列；手机在目录上方内联展开。

### 4.3 卡片和详情

- 卡片保持约 126px 高，显示得意黑编号、类型、难度、轮数、完成状态与两个身份的最佳评级。
- 详情使用思源宋体场景标题，完整展示时间地点、前情、目标、难度、轮数和当前对手。
- 当前卡片使用初音色左侧内条和浅薄荷底，不使用大幅缩放。

## 5. 对话页

### 5.1 桌面布局

桌面端使用固定三栏和顶部栏：

1. 故事栏：主题、目标、时间地点、完整前情和当前变化。
2. 聊天栏：关系进展、完整历史和统一输入框。
3. 形象栏：立绘或本轮生成的图像/视频。

页面高度为视口高度，三栏各自管理内部滚动。`<=900px` 时改为故事、形象、聊天顺序；聊天区域保留至少 620px 高，避免输入框遮挡历史。

### 5.2 关系进展

唯一公开进度为：

```text
round((warmth + openness + (100 - pressure)) / 3)
```

结果限制在 0–100，文案分段为：0–24 疏离、25–44 紧绷、45–64 试探、65–79 靠近、80–100 稳定。不得展示内部指标、delta 徽章或局势分析。

### 5.3 历史和语音

- 角色与玩家消息只在时间顺序历史中出现一次。
- 用户停留在旧消息时，新回复不得强制滚底；显示“回到最新”。玩家主动发送后回到底部。
- 每条角色消息带独立扬声器按钮。播放另一条消息前停止上一条；离开对话页时停止并释放音频。
- 语音输出模式继续自动播放最新角色消息。

### 5.4 输入框

- 输入框是一个 Codex 风格统一圆角容器，不再拆成文本框和外置操作栏。
- 文本区自动从一行增长到五行；Enter 发送，Shift+Enter 换行。
- 设置、麦克风和圆形发送按钮位于容器内。超过 200 字才显示 `当前/240`。
- 忙碌、录音和错误状态均在容器内表达。
- 手机使用 16px 输入字号，避免浏览器自动缩放。

### 5.5 形象与媒体

- 默认展示动态情绪立绘。
- 图像/视频成功后替换形象栏主体；加载时保留人物轮廓并覆盖轻量状态。
- 失败时保留立绘，只显示“已回到角色立绘”，不得暴露供应商或用量。

## 6. 其他组件

- 身份简报和结算页沿用同一 Logo 与字体分工。
- 结算可以显示分数和最终“关系进展”文字，不再显示两条内部指标、Token、成本或“评判 AI”。
- 主按钮使用深初音色实心；次按钮白底描边。所有交互都必须有 `:focus-visible`。
- 圆角容器使用 `--r-sm / --r-md / --r-lg / --r-pill`；阴影保持低饱和青灰，不使用彩色霓虹。

## 7. 动效和无障碍

- 屏幕入场使用 360ms 内的淡入和 8px 上浮。
- 卡片可做 40ms 阶梯入场；消息只在新增时入场。
- hover 位移不超过 2px，active 缩放范围为 0.97–0.99。
- `prefers-reduced-motion` 将动画和过渡降至 1ms。
- 页面必须保持一个清晰的 H1、可见键盘焦点、语义化 progressbar、描述性按钮名称和无横向滚动。
