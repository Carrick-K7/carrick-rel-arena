# 《关系修炼》设计系统

本文是前端视觉和交互的单一事实来源。品牌、字体、布局、动效或组件模式改变时，须同步更新本文和 `src/client/styles.css`。

## 1. 设计原则

1. **真实关系，不做数值面板**：界面围绕目标、前情、对话和对方形象组织。服务端可以保留多项内部指标，玩家只看到一条“关系进展”。
2. **初音色但不游戏化堆叠**：`#39c5bb` 是唯一品牌主色，用于选中、进度和关键操作。大面积使用纸白、浅薄荷和青灰。
3. **字体承担叙事层级**：展示字体负责记忆点，黑体负责操作，宋体负责故事。不同字体不混用职责。
4. **内容优先**：桌面端用三栏建立稳定位置；手机按故事、形象、对话顺序线性阅读，不横向滚动。
5. **隐私和技术实现退到幕后**：页面不展示供应商、Token、成本或“AI 实时生成”等技术状态。媒体失败直接回退立绘。

## 2. 品牌

### 2.1 Logo

- 品牌资产为 `public/brand/relationship-training-logo.svg`。
- 标志由两枚相扣的对话气泡组成“关系结”，使用初音青和深青。字标已转为 SVG 路径，不依赖浏览器字体。
- favicon 使用同一枚关系结，位于 `public/favicon.svg`。
- 页面使用 `BrandLogo` 组件；完整宽度约 178px，紧凑版约 138px。不得恢复圆圈“修”字或英文副标。
- 可访问名称统一为“关系修炼”或具体动作，例如“返回关系修炼关卡”。

### 2.2 色板

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f5f8fc` | 页面底色（Carrick 门户同款灰蓝） |
| `--surface` | `#ffffff` | 卡片、聊天气泡面板和浮层 |
| `--ink` | `#0f172a` | 主文字 |
| `--muted` | `#5b6b80` | 次要文字 |
| `--faint` | `#94a3b8` | 标签、占位和辅助信息 |
| `--line` | `#e2e8f0` | 主分隔 |
| `--line-soft` | `#eef2f7` | 弱分隔和轨道 |
| `--accent` | `#39c5bb` | 品牌主色（与 Carrick 门户一致），用于选中、进度和关键操作 |
| `--accent-dark` | `#0f766e` | 文字、按钮和 hover |
| `--accent-soft` | `#e6f7f5` | 选中 chip、玩家气泡和 hover 浅底 |

## 3. 三层字体体系

字体均为自托管 WOFF2，使用 SIL OFL 1.1。得意黑保留完整字形，避免 Hero 文案更新后发生逐字回退；思源黑体和思源宋体使用产品常用字子集。授权文件随静态资源一同发布。

| CSS family / token | 来源 | 使用范围 |
|---|---|---|
| `Relationship Display` / `--font-display` | 得意黑 | Hero 标题、首页章节标题、关卡大编号和少量展示数字 |
| `Relationship Sans` / `--font-sans` | 思源黑体 SC | 导航、正文、筛选、目标、玩家消息、输入框和所有控件 |
| `Relationship Serif` / `--font-serif` | 思源宋体 SC | 场景名、角色消息、开场白、剧情变化和结算叙事 |

约束：

- 得意黑不能进入按钮、正文、聊天和长段阅读区域。
- 角色台词用宋体左对齐；玩家消息用黑体右对齐。
- 生僻字允许回退至 `PingFang SC`、`Microsoft YaHei`、`Songti SC` 等系统中文字体。
- 全部字体使用 `font-display: swap` 作为资源失败时的安全回退。入口预加载三套字体的实际字重，并在字体加载完成后才挂载应用，避免回退字体闪现；加载期间只显示不依赖字体的 SVG Logo。
- 自动化测试必须检查 Hero 的每个字都由自托管得意黑渲染，不能只检查 CSS `font-family` 名称。
- 字体资源和授权文件均放在 `public/fonts/`，不使用字体 CDN。

## 4. 首页

### 4.1 信息结构

- 顶栏只显示 Logo 和圆形设置按钮。
- Hero 收敛为一条紧凑横带：左侧得意黑主标题，右侧三条带解释的优势（真实场景、自由表达、多模态演出）；不叠加眉题、口号或独立优势条。
- 场景浏览器为「顶部筛选工具栏 + 卡片网格」：不再有侧栏筛选和详情预览面板。
- 整张场景卡就是进入身份简报的入口，点击直达 `/scenarios/:scenarioId`，没有中间的选中态。

### 4.2 筛选

- 完成状态为 `.segmented` 分段单选：全部、未完成、已完成。
- 类型和难度为 `.chip` 多选；组内 OR、组间 AND。
- 工具栏右端显示 `可见 / 总数 个场景`；存在生效筛选时出现「清除筛选」。
- 移动端工具栏自然换行，不做折叠。

### 4.3 卡片

- 卡片为白色面板：得意黑关卡号水印、类型/难度/轮数小标签、宋体标题（两行截断）、底部完成状态与两个身份的最佳评级。
- hover 上浮 2px、accent 描边和 `--shadow-2`，不使用大幅缩放。
- 已完成且生成过媒体的关卡在卡片底部显示「查看回忆 N 次」，进入该章回忆库。
- 网格为 `repeat(auto-fill, minmax(min(300px, 100%), 1fr))`，桌面四列、平板递减、手机单列。

### 4.4 页面导航

- 筛选属于首页局部状态，不改变 URL。
- 卡片点击直接进入 `/scenarios/:scenarioId`；开始挑战进入 `/sessions/:sessionId`；结算进入 `/sessions/:sessionId/result`；“查看回忆”进入 `/scenarios/:scenarioId/memories`。
- 浏览器前进、后退与刷新必须恢复对应页面。对话仅在服务端会话 TTL 内恢复；过期后回到关卡目录并显示明确提示。
- 结算替换当前对话历史项；显式“返回关卡”回到本次应用浏览起点，不制造反复回到刚离开页面的历史循环。
- 每个路由根据场景或结局更新文档标题。

## 5. 对话页

### 5.1 桌面布局

桌面端使用固定三栏和顶部栏：

1. 故事栏：主题、目标、时间地点、完整前情和当前变化，直接排在中性页底上。
2. 聊天栏：悬浮白色面板（`--r-lg` + `--shadow-1`），内含关系进展、完整历史和统一输入框。
3. 形象栏：立绘或本轮实时生成的剧情图片；本局视频只在结算页出现。

页面高度为视口高度，三栏各自管理内部滚动。桌面端首页同样固定在一个视口内，页面本身不滚动，关卡网格独立滚动。`<=900px` 时恢复文档流并改为故事、形象、聊天顺序；聊天区域保留至少 620px 高，避免输入框遮挡历史。

### 5.2 关系进展

唯一公开进度为：

```text
round((warmth + openness + (100 - pressure)) / 3)
```

结果限制在 0–100，文案分段为：0–24 疏离、25–44 紧绷、45–64 试探、65–79 靠近、80–100 稳定。不得展示内部指标、delta 徽章或局势分析。

### 5.3 历史和语音

- 角色与玩家消息只在时间顺序历史中出现一次。
- 消息使用气泡：角色消息为浅灰（`#f1f5f9`）左对齐气泡、宋体，左上角小圆角；玩家消息为 `--accent-soft` 右对齐气泡、黑体，右上角小圆角。等待中的角色回应以同形灰气泡加呼吸脉冲呈现。
- 角色名 ·「开场 / 第 X 轮」与独立扬声器按钮组成气泡上方的紧凑 meta 行；玩家气泡不显示“你 · 数字”等内部回合记号。
- 角色动作说明作为斜体弱色舞台提示，位于 meta 行与气泡之间；形象栏底部不得重复显示动作说明。
- 用户停留在旧消息时，新回复不得强制滚底；显示“回到最新”。玩家主动发送后回到底部。
- 每条角色消息带独立扬声器按钮。播放另一条消息前停止上一条；离开对话页时停止并释放音频。
- 语音输出模式继续自动播放最新角色消息。

### 5.4 输入框

- 输入框是一个 Codex 风格统一圆角容器，不再拆成文本框和外置操作栏。
- 键盘焦点只由外层圆角容器呈现，textarea 本身不得出现第二层矩形描边或阴影。
- 文本区自动从一行增长到五行；Enter 发送，Shift+Enter 换行。
- 设置、麦克风和圆形发送按钮位于容器内。超过 200 字才显示 `当前/240`。
- 忙碌、录音和错误状态均在容器内表达。
- 手机使用 16px 输入字号，避免浏览器自动缩放。

### 5.5 形象与媒体

- 默认展示动态情绪立绘。
- 图像或视频输出模式都会在开场及每轮回复后生成一张 4:5 竖幅剧情图。每张图固定参考秋雾、江影的仓库原型图，并尽可能参考上一张成功图片；脸型、发型、年龄、服装和镜头轴线保持一致，只让眼神、嘴角、动作与人物距离渐进变化。
- 图片成功后替换形象栏主体；加载时保留人物轮廓，并显示预计百分比、生成阶段和已等待时间。Seedream 不返回任务内实时百分比，因此界面必须明确使用“预计”，运行中最多显示 96%，只有成功结果才显示 100%。
- 形象栏提供按开场和回合排列的横向缩略时间轴；默认跟随最新一轮，玩家可切换任意已生成画面比较表情与姿态变化。
- 排队、生成、失败状态必须在对应时间轴节点上可辨认；失败或超时后显示“重新生成”，不得无限保留加载动画。
- 模型只生成纯净画面，不在位图中生成文字。玩家和角色的原始台词由 `MemoryFrame` 以 HTML/CSS 对话气泡叠在图片内，玩家气泡靠右、角色气泡靠左，保证说话人清晰且汉字准确、可访问、可复制。
- 剧情图片本身即为完整的记忆画面，不在底部增加“第 X 轮”“这一刻”或技术实现说明等图注栏；回合归属由形象轨迹和对话历史表达。
- 视频输出不逐轮生成视频。结算后选取开场、评判关键轮次和结局图片，连同固定人物原型一次性生成 15 秒无声“本局回忆”；结算页继续用真实对话数据展示准确中文。
- 为避免一张约一分钟的供应商生成时间被逐轮串行放大，客户端最多并行提交三张剧情图。每张图始终使用固定人物原型，并在提交时尽可能附带最近一张已成功的本局画面；这是角色连续性与等待时间之间的折中。整局视频在结算后立即与剩余剧情图并行启动，不等待所有逐轮图片完成。
- 逐轮剧情图默认生成 1K 预览规格，以匹配界面中的实际展示尺寸并缩短等待；15 秒 Seedance 回忆视频通常仍需数分钟。视频服务端保留十分钟任务窗口，避免接近完成的上游任务被本地轮询误判为超时。
- 图像和视频偏好可以保存在本机，媒体密钥不能保存。刷新后若影像偏好仍处于启用状态，形象栏和结算页必须显示“重新解锁”，不得把尚未提交的任务显示成排队或生成进度。
- 失败时保留立绘，只显示“已回到角色立绘”，不得暴露供应商或用量。
- 已完成章节允许把稳定图片/视频 URL、回合标签、完成时间、身份和评级写入本机回忆索引；视觉节拍详情、会话 ID和对话正文不得写入浏览器持久化存储。

## 6. 其他组件

- 模态设置不提供输入单选：文字输入与浏览器支持时的语音转写并列展示为常驻能力。
- 输出使用复选语义。文字固定启用且不可取消；语音、图像、视频可以分别启用、组合或关闭。
- 设置面板只解释能力和必要的媒体解锁，不重复显示“当前模式”、缓存策略或技术性状态摘要。
- 身份简报由一个白色面板承载情景、目标、人物和扮演选择，分区用发丝线分隔；挑战目标用 `--accent-soft` 底和 accent 左边条强调。
- 结算可以显示分数和最终“关系进展”文字，不再显示两条内部指标、Token、成本或“评判 AI”。评级和分数等展示数字使用得意黑。
- 结算页必须提供“本局档案”：按开场、逐轮对话和结局的时间顺序展示双方原话、舞台动作及每轮剧情图状态；已经生成的图片可逐张回看，整局回忆视频作为最后一件制品单独展示。生成中或失败的制品仍保留对应轮次和明确状态，不能只显示最后一张图。
- 已完成且生成过媒体的关卡在卡片底部显示“查看回忆”。回忆库按完成时间倒序展示历次制品，每局包含全部成功图片和至多一支整局视频；页面明确说明不保存对话正文。
- 共享基元：`.panel`（白底卡片，场景卡、简报面板、聊天面板、回忆卡片复用）、`.chip`（pill 筛选钮）、`.segmented`（分段控件）、`.header-icon-button`（顶栏圆形图标钮）。主按钮使用 `--accent-dark` 实心白字；次按钮白底描边。所有交互都必须有 `:focus-visible`。
- 圆角容器使用 `--r-sm / --r-md / --r-lg / --r-pill`；阴影为 slate 基低饱和阴影，不使用彩色霓虹。

## 7. 动效和无障碍

- 屏幕入场使用 360ms 内的淡入和 8px 上浮。
- 卡片可做 40ms 阶梯入场；消息只在新增时入场。
- hover 位移不超过 2px，active 缩放范围为 0.97–0.99。
- `prefers-reduced-motion` 将动画和过渡降至 1ms。
- 页面必须保持一个清晰的 H1、可见键盘焦点、语义化 progressbar、描述性按钮名称和无横向滚动。
